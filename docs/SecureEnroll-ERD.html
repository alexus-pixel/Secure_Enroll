Design decisions worth defending

Encrypt identifiers, not names

An encrypted column cannot be searched or sorted. Names stay in plaintext so the registrar can look up a pupil; the Learner Reference Number, birth date, contact number and address are encrypted, because nothing in the system needs to sort by them.

The blind index

We still need to catch a duplicate LRN. lrn_hash stores a SHA‑256 of the LRN beside the encrypted value: unique, checkable, and not reversible back to the number.

Duplicates die at the database

UNIQUE (student_id, school_year_id) makes a double enrollment impossible even if two parents submit at the same instant. Validation in React is a courtesy; the constraint is the guarantee.

The audit log is append-only

No route in the API issues UPDATE or DELETE against audit_logs. A record that can be edited proves nothing, which is the whole point of non-repudiation.

Roles are rows, not strings

Adding a principal or a cashier role later means one INSERT and a few permission grants. Hardcoding if (user.role === 'admin') across the codebase is how the excessive-privilege problem in the literature starts.

Files live outside the web root

documents.file_path points at storage the web server will not serve directly. Downloads go through an authenticated route that checks the permission first, and checksum proves the file was not swapped afterwards.

Application status flow

The status column on enrollment_applications accepts six values, and a CHECK constraint rejects anything else. Only a user holding application.approve can move a record into the last two.
